# 인스타에서 '공유'로 카드 만들기

릴스를 보다가 **공유 → 보드**를 누르면 카드가 바로 만들어집니다.
링크를 복사해서 사이트를 열고 붙여넣던 걸 두 번 탭으로 줄이는 게 목적입니다.

> 카드는 **묻지 않고 바로 저장**됩니다. 공유를 눌렀다는 건 저장하겠다는 뜻이 이미
> 분명하니까요. 대신 AI가 채운 게 마음에 안 들 수 있어서 하단에 뜨는 알림에
> **수정하기** 버튼을 같이 둡니다.

---

## 앱은 어떻게 링크를 받나

안드로이드와 아이폰이 공유를 넘겨주는 방식은 완전히 다르지만,
**둘 다 결국 이 주소를 여는 것으로 귀결**되도록 만들었습니다.

```
https://jjazzking.github.io/hyejinjungwoocontentsboard/?url=…&text=…&title=…
```

앱은 뜰 때 이 세 칸을 훑어서 인스타/유튜브/틱톡 링크를 찾고, 찾으면 카드로 만든 뒤
주소창에서 파라미터를 지웁니다 (안 지우면 새로고침할 때마다 같은 카드가 또 생깁니다).

세 칸을 다 보는 이유가 있습니다. **인스타는 링크를 `url`이 아니라 `text`에 문장째로
담아 보내는 경우가 많습니다** — "이거 봐 https://…" 처럼요. 그래서 어느 칸에 들어오든
`extractSnsUrl()`이 텍스트에서 링크만 뽑아냅니다.

같은 게시물을 두 번 공유해도 카드는 하나만 생깁니다. 공유로 들어오는 링크에는
`?igsh=…` 같은 추적 값이 매번 다르게 붙어 오는데, `normalizeSnsUrl()`이 그걸 떼고
`www.` 유무·끝 슬래시까지 맞춰서 비교하기 때문입니다.

## 안드로이드 — 홈 화면에 추가하면 끝

1. **크롬**으로 https://jjazzking.github.io/hyejinjungwoocontentsboard/ 열기
2. 우측 상단 **⋮** → **홈 화면에 추가** (또는 **앱 설치**)
3. 끝. 이제 인스타에서 릴스 → **공유** → 목록에서 **혜진♥정우** 선택

> 공유 목록에 안 보이면 **더보기/기타**를 눌러 전체 목록을 펼쳐 보세요.
> 그래도 없으면 홈 화면 추가가 안 된 겁니다 (아이콘이 홈 화면에 있는지 확인).
>
> ⚠️ **삼성 인터넷 등 다른 브라우저로 추가하면 동작하지 않을 수 있습니다.**
> 크롬으로 추가하세요.

## 아이폰 — 단축어를 하나 만들어야 합니다

애플은 웹사이트를 공유 시트에 직접 올리는 표준(Web Share Target)을 지원하지 않습니다.
대신 **단축어 앱**으로 같은 일을 할 수 있고, 한 번만 만들면 그 뒤로는 안드로이드와 똑같습니다.

1. **단축어** 앱 → 우측 상단 **+**
2. 위쪽의 단축어 이름을 **보드에 저장** 으로 바꿉니다 (공유 시트에 이 이름으로 뜹니다)
3. **정보(ⓘ) 버튼** → **공유 시트에 표시** 켜기
   - 바로 아래 **입력 종류**에서 **URL** 과 **텍스트** 만 남기고 나머지는 끄세요
4. 액션 추가 → **URL** 검색 → **URL** 액션을 넣고, 주소칸에 아래를 넣습니다

   ```
   https://jjazzking.github.io/hyejinjungwoocontentsboard/?text=
   ```

5. 그 `?text=` **바로 뒤에 커서를 두고**, 변수 목록에서 **단축어 입력**을 끼워 넣습니다
6. 액션 추가 → **URL 열기** 를 그 아래에 붙입니다
7. 완료

이제 인스타에서 릴스 → **공유** → **기타** → **보드에 저장**.

> **홈 화면에도 추가해두면** 사파리 주소창 없이 앱처럼 열립니다.
> 사파리로 사이트를 열고 **공유 → 홈 화면에 추가**.

## 잘 안 될 때

| 증상 | 확인할 것 |
| --- | --- |
| 공유 목록에 앱이 없음 | 안드로이드: 크롬으로 홈 화면에 추가했는지 / 아이폰: 단축어의 '공유 시트에 표시'가 켜져 있는지 |
| 앱은 열리는데 카드가 안 생김 | 주소창에 `?url=` 또는 `?text=` 가 붙어 있는지. 없으면 공유가 링크를 안 넘긴 것 |
| "링크를 카드로 만들지 못했어요" | 인스타/유튜브/틱톡 링크가 아니거나, 텍스트에 링크가 없는 경우 |
| 같은 카드가 두 번 생김 | 링크가 정규화 대상 밖일 수 있음 — `normalizeSnsUrl()` 확인 |

**브라우저에서 바로 시험해볼 수도 있습니다.** 주소창에 이렇게 치면 공유와 똑같이 동작합니다.

```
https://jjazzking.github.io/hyejinjungwoocontentsboard/?url=https://www.instagram.com/reel/아무거나/
```

> ⚠️ `npm run dev` 로 띄운 개발 서버에서는 이 주소가 **403 Restricted** 로 막힙니다.
> Vite가 인코딩된 URL을 파일 경로로 오해해서 생기는 개발 서버만의 문제라,
> 배포된 사이트나 `npm run build` 결과물에서는 정상 동작합니다.
> 로컬에서 확인하려면 빌드한 `dist/` 를 정적 서버로 띄우세요.

## 구현 메모

| 파일 | 역할 |
| --- | --- |
| `public/manifest.webmanifest` | `share_target` 선언 — 안드로이드 공유 시트에 뜨게 하는 부분 |
| `public/sw.js` | **일부러 아무 일도 안 하는** 서비스 워커. '설치 가능한 앱' 조건을 채우려고만 있음 |
| `src/hooks/useSharedLink.js` | 주소에서 공유 파라미터를 한 번 읽고 지운다 |
| `src/components/ShareToast.jsx` | 저장/중복/실패 결과를 알리는 하단 띠 + 수정하기 |
| `src/utils/linkAnalyzer.js` | `normalizeSnsUrl()` — 추적 파라미터 제거로 중복 방지 |

서비스 워커에 캐싱을 넣지 않은 건 의도입니다. 카드 데이터는 Supabase에 있어서
오프라인으로 얻는 게 거의 없는 반면, 캐시를 깔면 **배포한 뒤에도 옛날 화면이 남는**
문제가 생깁니다.
