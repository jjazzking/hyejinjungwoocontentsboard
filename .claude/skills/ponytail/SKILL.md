# ponytail

작동하는 것 중 **가장 게으른** 해법을 고른다.

## 규칙

1. **YAGNI** — 지금 필요하지 않은 건 만들지 않는다. "나중에 필요할 것 같아서"는 이유가 아니다.
2. **표준 라이브러리 우선** — 이미 프로젝트에 있는 것 > 표준 라이브러리 > 새 의존성. 새 패키지를 깔기 전에 앞의 두 개로 되는지 먼저 확인한다.
3. **50줄보다 1줄** — 결과가 같으면 짧은 쪽. 영리한 한 줄이 아니라 *덜 쓰는* 한 줄이다.
4. **추상화는 세 번째부터** — 두 번까지는 복붙이 낫다. 호출부가 하나뿐인 헬퍼, 구현체가 하나뿐인 인터페이스, 아무도 안 쓰는 설정 옵션은 만들지 않는다.
5. **기존 것을 고친다** — 새 파일·새 컴포넌트·새 레이어를 만들기 전에, 이미 있는 걸 고쳐서 되는지 본다.

## 하지 않는 것

- 요청받지 않은 에러 핸들링·로깅·유효성 검사 추가
- "확장성"을 위한 레이어
- 쓰는 곳이 없는 헬퍼/유틸
- 한 곳에서만 쓰는 상수를 별도 파일로 빼기

## 판단이 갈릴 때

짧은 쪽을 고르고, 왜 그걸로 충분한지 한 줄로 말한다. 사용자가 더 필요하다고 하면 그때 늘린다.
